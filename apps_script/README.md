# Google Apps Script para Google Sheets (SIRE + Comprobantes)

Esta carpeta contiene el código de Google Apps Script que corre en la hoja de cálculo de Google Sheets conectada a este repositorio.

## Archivos incluidos:
- `Config.gs`: Parámetros de configuración (Token de GitHub, Propietario, Repositorio, URL base de Cloudflare R2 / Webhook).
- `GitHubSync.gs`: Sincronización e importación automática de los reportes CSV descargados (Compras, Ventas, Histórico) y menú de ejecución de workflows.
- `Webhook.gs`: Endpoint de Web App para recibir avisos instantáneos de GitHub Actions cuando finaliza cada empresa/periodo. Al subir el código, `deploy-appsscript.yml` también pasa la Web App a la versión nueva (si no, lo que llega por GitHub corre código viejo, p. ej. el Panel sin Resumen IGV e IR).
- `appsscript.json`: Manifiesto de configuración de Apps Script.
- `MesAnterior.gs`: menú **📅 Descarga automática del mes anterior**. El interruptor es el bloque `mes_anterior` de `empresas.json`; la corrida programada de la 1:00 AM hora Perú de **SIRE completo** (`sire-cadena-completa.yml`) lo revisa y, si está activo y hoy es uno de sus días (por defecto 3 y 11), agrega el mes anterior de todas las empresas activas antes del mes actual. Se activa/desactiva/cambia desde este menú, desde GitHub (Run workflow de *SIRE completo* con la opción `mes_anterior`) o editando `empresas.json`.
- `SoloReporte.gs`: menú **⚡ Actualizar solo reporte SIRE (rápido, sin PDF/XML)**. Pregunta empresas (números de la lista, RUC o vacío = todas), mes `AAAAMM` o rango `AAAAMM-AAAAMM` (máx. 36 meses, no futuros) y compras/ventas/ambos, y lanza `sire-solo-reporte.yml`: solo el registro del SIRE por la API oficial, todas las empresas a la vez (los meses de cada una, uno tras otro), sin navegador ni PDF/XML. Guarda en el mismo lugar que la descarga completa (`sire/<RUC>/historico/<AAAAMM>/`) y no toca los archivos "más recientes" de la diaria. Al terminar cada empresa, el webhook importa esos meses a Drive (y la Liquidación IGV); sin webhook queda un seguimiento automático (`SEGUIMIENTO_WORKFLOW`). También desde Telegram (`/sire`) y WhatsApp (`sire …`).
- `ComprasCompleto.gs`: pestaña **Compras SIRE completo** en cada Liquidación IGV (solo compras). Junta todas las facturas del año de las **propuestas y aceptadas** de SUNAT (GitHub las guarda por mes como `historico/<AAAAMM>/compras_propuesta.csv` y `compras_aceptada.csv`, convertidas de los .zip por `scripts/sire_versiones_compras.py`), **una sola vez cada una** con prioridad Aceptada > Propuesta, y agrega al final: Estado SIRE (✅ Anotada · 🟡 No anotada, quedó fuera de la aceptada · 🔵 En propuesta de un mes aún sin aceptada), periodo en que se anotó, propuestas en que apareció y "Anotar hasta" (12 meses, referencial). **Detalle Compras** no cambia (sigue alimentando el IGV); solo se le agrega al final la columna **Fuente SIRE** (Aceptada / Propuesta).
- Menú **8. Generar/Actualizar liquidación IGV**: escribe un RUC para una sola empresa o deja en blanco para **todas las activas**. Si no alcanzan los 6 minutos de Google, sigue sola en segundo plano (trigger `continuarColaLiquidaciones`) y deja el resumen en la pestaña Registro.
- **Descarga diaria puntual:** la dispara esta hoja a la 1 AM (⏰ Programar ejecución automática diaria) con la marca `diario`; el cron de GitHub (4:17 AM) es solo respaldo y no repite si ya corrió (run-name "SIRE diario …" + `concurrency`). El aviso de GitHub (`doPost`) responde al instante y deja la importación en una **cola** (`procesarColaWebhook`, una empresa a la vez, con candado), así GitHub no espera ~5 min por empresa.

## 🧪 Prueba: reporte SIRE directo (sin GitHub) — `SireDirecto.js`
Menú **SIRE SUNAT → 🧪 Prueba: reporte SIRE directo desde Apps Script (sin GitHub)…**. Baja el registro de compras o ventas de UNA empresa y UN mes hablando directo con la API SIRE desde Google (como el antiguo SireClient.gs), mide cuánto tarda cada paso, cuenta los comprobantes, puede buscar uno (ej. `FN01-80`) y guarda el ZIP y el TXT en la carpeta de Drive «SIRE · prueba directa (Apps Script)». **No escribe en las liquidaciones.** Las credenciales (usuario/clave SOL, client_id/secret) se escriben en la ventana y quedan solo para quien las escribe (UserProperties); «🧪 Borrar credenciales de la prueba directa» las quita. Si `Utilities.unzip` no abre el ZIP de SUNAT, usa un lector propio (`SDIR_unzip_`).

## ✔️ Verificación de cada comprobante en la Liquidación IGV — `LiquidacionVerificar.js`
Al generar la liquidación se agregan al final de **Detalle Compras** y **Detalle Ventas** (después de «Origen»): **N/C aplicadas**, **N/C (detalle)**, **Total neto**, **Detracción pagada S/**, **Constancia detracción**, **SSCO** y **Validez SUNAT**; y en el tablero **Liquidacion**, **SIRE Ventas / SIRE Compras** por mes (✅ Presentado / 🔵 Propuesta / —). La validez la llena el menú **✅ Validar comprobantes con SUNAT (API Consulta Integrada)…**: pide una sola vez el client_id y client_secret de la API (Consulta Integrada usa `client_credentials`, sin usuario ni clave SOL), consulta lo que falta (10 a la vez), sigue sola en segundo plano y guarda las respuestas en la pestaña oculta `_Validez`.
